## Lec 1 概论
操作系统位于硬件（CPU, RAM, 磁盘等）和用户应用程序之间，提供进程、内存管理、文件系统等服务。其目的是：在多个应用间复用硬件、隔离应用以保证安全、在应用间共享数据、抽象硬件以提供便利。

UNIX的设计哲学：

> 1.提供机制，而非策略：内核提供fork, exec, pipe这些基础机制，至于如何用它们来实现I/O重定向或流水线，那是Shell（一个普通用户程序）的策略，内核不关心。  
2.一切皆文件：用文件描述符作为统一接口，程序可以同等对待硬件设备、普通文件、管道甚至网络连接，极大地简化了编程。   
3.组合的力量：单个系统调用（fork, exec等）看起来功能有限，但它们的**组合性**赋予了系统无限的可能性。像Shell这样的普通程序，可以通过编排这些基础原语，构建出极其复杂和强大的功能。


## Lec 2 c语言简介
 C语言适合底层编程，C的指令和类型能很好地映射到RISC-V指令和硬件结构；它运行时开销极小，能直接访问硬件；
它有显式的内存管理（无垃圾回收），让内核完全掌控内存；它是编译型语言，效率高；它是构建系统软件的主流语言。
> 一言以蔽之，C语言可视为一种可移植的、带有结构化语法的汇编语言，能够很好地构建操作系统底层结构。


## Lec 3 OS设计
操作系统设计的核心目标：**隔离**。通过引入进程、虚拟内存、文件等核心抽象，为每个程序创建了一个独立的、受保护的“沙盒”，从而建立秩序。

操作系统设计的核心安全哲学：**零信任用户**。即假设用户代码是恶意的，会主动尝试打破隔离；而内核代码是可信的。为防御用户代码，内核依赖两大组件：
> 1.硬件层面对用户指令的控制。  
2.谨慎的系统调用接口和实现。

其中硬件层面的隔离主要体现在
> 1.user/supervisor mode:
内核运行在supervisor mode，能执行特权操作，比如设备读写，修改页表。  
2.虚拟内存:
限制单个用户进程使用的内存，操作系统设置page table用于控制每个进程只能
访问它自己的内存。

谨慎的系统调用：
系统调用必须在supervisor模式下执行。应用程序通过一个特殊的 ecall 指令来请求系统调用。ecall 会：
> 1.切换到supervisor模式。   
2.跳转到内核中一个预先设定的、已知的代码入口点。


内核架构主要分为:
> 宏内核 vs. 微内核  
宏内核是一个包含了所有系统调用实现的大型程序（xv6, Linux都是如此）。  
优点是子系统间合作容易，性能好；  
缺点是内部交互复杂，容易产生bug，且内核内部缺乏隔离。  
微内核则将大部分功能（驱动、文件系统等）移到用户进程中，以减小内核bug的破坏范围。


简要的启动流程:  
> 1.main() 初始化 xv6 内核和硬件。  
userinit() 创建一个进程,  
内核在 forkret 处启动该进程。  
forkret 调用 exec("/init") 然后“返回”到用户空间。  
2.init 进程：顶层进程。  
拥有控制台文件描述符 0 和 1。  
通过系统调用来启动 shell 进程。   

典型的系统调用kexec: 
> 从磁盘读取文件,
解析 “ELF” 格式,  
包含代码段和数据段,   
进行大量检查，防止被欺骗从而覆盖内核内存，  
分配栈，  
将参数写入栈上。
